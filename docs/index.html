What makes it compound

Your sessions forget. Your notes don't.

Long sessions get compacted — older turns are squeezed or silently dropped, and the decision you made on day one goes with them. Every session here keeps a notes.md next to its code: the goal, the decisions, the next steps, and the session id. Pick the work back up weeks later, in a fresh conversation, with the thread intact.

Written as you go

/save-session checkpoints the work mid-flight; /close-session wraps it up with a summary.

Reloaded into a fresh chat

/restart-session briefs a brand-new conversation from the notes — plus every past session id, so the chain back is never broken.

Or replayed verbatim

Because the session id is recorded, claude --resume <id> still gives you the original transcript, turn for turn.

A file you own

The source of truth is markdown on your disk — not a context window, and not someone's cloud.

And across sessions

A lesson that outlives its session.

A notes.md remembers one session. The decision that cost you an afternoon deserves to outlive it. Each space can point at a folder of knowledge notes: the agent writes into it as it learns — and the next investigation starts by reading it back — so you stop re-deriving from the code what a past session already settled.

It is a plain folder of Markdown, so no tool is required to read it. Obsidian is a pleasant way to browse it — so are VS Code, Logseq, or grep.

Written the moment it's learned

/learn writes one atomic note as soon as something durable comes up — a preference you stated, a gotcha and its workaround. Waiting for the session to close means depending on a gesture that often never comes.

Extended, not duplicated

A fifth note on one subject dilutes retrieval instead of adding knowledge. It searches first and extends or corrects the note that already owns the subject — then links it into the index, because an orphan note is one nobody finds.

Distilled, not dumped

/close-session promotes only the high-signal decisions, and marks the source, so the same bullet is never promoted twice.

Read back before you dig

/route <ticket> builds a Context Brief from those notes, your past sessions and your tracker — before you open the code. It resolves which folder to read from the session's space.

And it writes its own skills

A mistake you fix once, it stops making.

Notes record what is true; a skill records how to do something. When a session actually teaches a procedure — a dead end whose workaround is worth keeping, an approach you corrected — /skill-propose drafts it. Nothing becomes active on its own: proposals are staged outside the skills folder, and you read the diff before anything runs.

Staged, never live

/skill-propose writes to ~/.claude/skills-pending/ and never to ~/.claude/skills/ — a new skill, or (preferred) a targeted patch to one you already have.

You are the only gate

/skills-review is the sole path from proposed to active. It shows the full content or a real diff first, and reports when the loop last produced anything — so a loop that silently died is visible.

Curated, never deleted

/skills-curate is the periodic pass over the whole set: it names the umbrella a cluster serves and stages merges or archives. Archived, not removed — recoverable, and only ever skills the agent proposed.

It only fires when it learned

The proposal step hangs off the session close, and stays silent unless the session met one of its criteria. A skill set that inflates on every session is worse than none.

The dashboard

Tabs don't scale. Agents do.

When you run many sessions in parallel, the bottleneck isn't the agents — it's you holding it all in your head. Which one needs an answer? Which finished an hour ago? Where does each one live?

Lay it all out in front of you, and the pile starts working for you. When it gets away from you anyway, Doctor reports what is genuinely broken — a session filed as closed while its process is still running, a frontmatter pointing at a conversation that no longer exists — and repairs only what you tick. Clean audits the rest by age and proposes what to archive.

Session skills

The dashboard is only half of it

A small set of Claude Code skills drive the lifecycle the dashboard visualizes, and the app keeps them current itself — it syncs them into ~/.claude/skills at launch, and copies aside anything you had edited before it overwrites. The script below is for installing them without the app.

# only if you want the skills without the app
$ git clone https://github.com/t-mercier/ai-agents-orchestrator
$ cd ai-agents-orchestrator
$ bash scripts/install.sh
  ✓ skills → ~/.claude/skills
  ✓ config seeded

# start a tracked session, from anywhere
$ claude
> /start-session FEAT 1842 checkout-redesign
  ✓ workspace + notes.md created
  ✓ now live in the dashboard

The session lifecycle

The five you type yourself. Each one moves a session between the states the dashboard shows.

/start-sessionCreate a session workspace + notes.md, register it, sync the repo.
/save-sessionCheckpoint mid-flight — the same summary as close, marked (in progress), without closing. Handy right before a context compaction.
/close-sessionWrap up — summarise into notes.md and append a history entry.
/restart-sessionReload a session's context from its notes into a fresh session.
/archive-sessionMark a session archived and drop it from the active list.

What the buttons run

The same work, headless. You press a control in the app; it runs one of these and never opens a terminal.

/wrap-sessionThe headless twin of /close-session — behind the Close button.
/sync-refsRealign a session's tickets and PRs with the tracker and GitHub — behind Sync.
/import-sessionAdopt an existing Claude Code session under a chosen space and category.
/rename-categoryRename a category everywhere at once — folder, notes, and config.

Memory across sessions

Two halves of one loop: one writes what was learned, the other reads it back before you dig.

/learnWrite what you just learned straight into the space's knowledge notes — or extend the note that already covers it.
/routeA Context Brief before you open the code: the knowledge notes, your past sessions and your tracker on one subject.

Skills that write skills

The learning loop, with you as the only gate. Nothing here can make a skill active on its own.

/skill-proposeStage what the session taught as a new skill, or a targeted patch to one you have. Never writes to the live skills folder.
/skills-reviewThe approval gate — diff, then promote or reject. The only path from proposed to active.
/skills-curatePeriodic pass over the collection: merge clusters, archive what went stale. Never deletes.

Local-first by design

It watches. It barely touches.

AI Agents Orchestrator is a projection of state Claude Code already writes to disk. It is silent on the network until you press Sync — that button is the opt-in, and it is the only thing that reaches GitHub or your tracker. It is read-only on your session data otherwise, writing only when you archive a session, save a PR link, or let it bring its own skills up to this version.

No shell strings

Every command spawns with separate args — no string interpolation, no injection surface.

Allowlisted inputs

Paths, branches and PR URLs are validated against strict patterns before use.

Sandboxed writes

The two writes (archive, PR link) are atomic and confined under your configured roots.

Offline until you ask

No timer, no telemetry, no background fetch. Nothing leaves the machine until you press Sync.

Read-only on ~/.claude No network calls until Sync No secrets stored 275 tests
